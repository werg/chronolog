# Working with Chronolog

Chronolog is the local-first deterministic undo-do-redo runtime for Tendriller and standalone peer applications: Ed25519/X25519 identity, flat timestamp-ordered operation sets, pure Merkle-DAG `CAS` (`ContentAddressedStore`), QuickJS-NG Import-Map ES Module reducers (`TopicKernel`), deterministic Merkle-paged SQLite+FTS5+`sqlite-vec` (`chronolog-db`), reactive views (`createLiveView`), local view stores (`createViewStore`), encrypted device checkpoints, durable event forwarding (`forwardSessionEvents`), scoped tools (`createScopedApplicationTools`), ephemeral signals (`@chronolog/signals`), and direct/relayed replication.

## Architectural Invariants

Read [the Chronolog v2 CRDT contract](docs/CRDT_CONTRACT.md).

- **Flat timestamp-ordered operation set:** Every replica derives the exact same order from `(authorTimestampMs, author, opId)`. No peer, host, checkpoint signer, transport receipt, or selected history assigns operation order.
- **Pure Merkle-DAG CAS & strict two-way partition:** On `privateLog: true`, `$*` control topics (`$reducers`, `$admission`, `$seals`, `$keys`, `$publications`, `$mounts`, `$builders`) are mutated ONLY by `visibility: 'public'` ops (which can read only `$*` topics and public CAS). Private topics are mutated ONLY by `visibility: 'encrypted'` ops. Idempotency is scoped by `(visibility, author, operationId)`. Blind hosts (`blindHostMode: true` / `replayBlindHostControl`) derive identical control state to full replicas through the one shared control-plane derivation (`materializeControl` in `packages/peer-session/src/control-plane.ts`). Encrypted envelopes do not carry `authorTimestampMs`, so a replica without a ring's key cannot order that ring's ops: `historyDigest`/`stateRoot` are ring-dependent on private logs (topics, outcomes and last-op ids are ring-scoped so reducer results never depend on which rings a replica decrypts).
- **Deterministic QuickJS-NG + Pure WASM + SQLite-CAS:** Fresh `QuickJSContext` per `reduce()`/`query()`/`describe()`/`authorize()`/`verify()`/`admit()` invocation with deep-frozen inputs (`state`, `tx`, `ctx.config`, `ctx.topic()`), lowercase-hex `ctx.logId` (`null` only for standalone `derive()`), `ctx.can()` + `ctx.reject()`, `reducer:crash` vs intentional rejection distinction, path-reporting strict JSON output validation, `chronolog:crypto` (`crypto@2`: SHA-256, HMAC-SHA256, Ed25519, NIST P-256 WebAuthn DER/compact), 2-arg scoped `chronolog-pkg/v1` resolution, per-package `builtins` attenuation, deterministic fuel metering (`limits.maxFuel`), non-deterministic globals stripped, uncatchable host-level `MissingDependencyError` interrupts, pure deterministic `WasmSandbox` (`chronolog:wasm` + `runtime: 'wasm-pure'`), and static `WebAssembly.Module` injection for Cloudflare Workers. SQLite-CAS binds `actor()`, `op_id()`, `operation_id()`, `op_time()`, `tx_visibility()`, `chronolog_can()`, `chronolog_topic()`, `chronolog_topic_last_op()`, `chronolog_op()`, `chronolog_author_last_op()`, and `chronolog_topic_query()` plus read-only eponymous virtual tables (`chronolog_tx`, `chronolog_topics`, query-only `chronolog_history`), disables `random()`/`randomblob()`, pins `datetime('now')` and `localtime` to UTC `op_time()`, and enforces `mode: 'admin' | 'user' | 'readonly'` + `chronolog/rls`.
- **Hybrid PQ `$keys`, Key-Tagged TreeKEM, Private Vaults, anonymous padded envelopes & compartment isolation:** Devices hold persistent Ed25519 + X25519 + hybrid PQ X-Wing (`ML-KEM-768 + X25519`) wrap keys; `$keys` enforces `policy` (`minSuite`, `distribution: 'flat' | 'tree'`, `paddingBucketBytes`, `hideEnvelopeAuthor`, `rotateOnRemove`, `maxOpsPerEpoch`), write-once lockboxes (grants only by an administrator, the member itself, or its `admittedBy` admitter), derived per-epoch `mailboxVerifyKey` tags, and Key-Tagged TreeKEM (`rotateTreeEpoch` / `chronolog-keytree/v1`, `openTreeEpoch` checked against the on-log `keyCommitment`, `needsRotation` healing; $O(\log N)$ boxes once internal nodes are populated, at most one per other active member otherwise); a removal must be preceded in the same op by rotations of every ring whose latest epoch the member holds; `TopicKernel` enforces `$keys.topicRings` fail-closed and `$keys.policy.maxOpsPerEpoch` (accepted encrypted ops per `(ring, envelope epoch)` in canonical order, excess rejected `epoch_op_budget_exhausted`); envelopes use the single `hkdf-aes-256-gcm` suite (24-byte `ENVELOPE_NONCE_BYTES` HKDF salt, per-op AES-256-GCM subkey + IV, ciphertext = padded plaintext + 16-byte tag); host attestations are `chronolog/host-attestation/v2` payloads bound to `logId` and `expiresAtMs`; `chronolog/vaults` + `session.vaults` provide encrypted-partition Private Capability Vaults with $O(1)$ adds, per-vault forward-secret removals, and `unsealRows()`; `chronolog/rls` provides write-time `sealRecipientsPolicy` & `vaultBoxPolicy`; and `session.sealFor()`/`unseal()` provide selective per-recipient encryption.
- **Offline authoring & reconnect rewrapping:** Author locally and durably before network delivery. Encrypted envelopes are reconciled by `encryptedEnvelopeDigest` so rewrapped offline operations sync cleanly past undecryptable older epochs while preserving original `opId`, `authorTimestampMs`, and signature.
- **Unified state-defined `$admission` & kernel-enforced `$seals`:** `$admission` unifies per-operation fail-closed global authorization (`authorize`, with monotonic per-topic attenuation), optional cross-topic semantic post-conditions (`verify(before, after, tx, ctx)`), ephemeral signal rules, and protocol-agnostic history admission (`admit(state, { logId, ops, evidence, pinnedFrontier }, ctx)` supporting `open`, `signed-frontier`, `threshold-quorum`, `member-quorum` (signers: administrators, or members holding the policy's `scope`; there is no finalizer role), `optimistic-challenge`, `merkle-anchor`, `pinned-checkpoint`, and surgical non-rewinding `pinnedFrontier` descent). `$seals` is a plain-data, kernel-enforced monotonic immutability table pinning resolved reducer CAS hashes and `frozen`/`append-only` JSON paths irreversibly.
- **Zero native C/C++ builds:** Node durable storage uses Node 22+ built-in `node:sqlite` (`DatabaseSync`). No `better-sqlite3`, no `@dolthub/doltlite`, no `node-gyp`.

## Package Boundaries

- `packages/canonical`, `packages/crypto`, `packages/protocol`: deterministic CBOR, v2 Genesis/Operation/Envelope wire formats, and the ONE Ed25519 verification rule set (`verifyEd25519Sync` in `packages/protocol`, `@noble/ed25519` strict `zip215: false`; `verifyEd25519`/`verifyDomain`, `@chronolog/crypto`, authority records and `chronolog:crypto` all delegate to it). `packages/crypto`: X25519/RFC 9180 HPKE, hybrid X-Wing, epoch payload AEAD, Key-Tagged TreeKEM (`keytree.ts`).
- `packages/records`: `BytesStore` (`MemoryBytesStore`, `NativeBytesStore` via built-in `node:sqlite`, `IndexedDbBytesStore`), `ContentAddressedStore` (Merkle-DAG CAS with public/private partitions and exact mark-and-sweep GC), framed peer channels.
- `packages/authority`: portable signed records, canonical `ApplicationDescription` input schemas, protocol-agnostic admission evaluation (`evaluateAdmission`, `AdmissionEvidence`, `PinnedFrontier`), and `signHostAttestationV2`. Zero eager materializer/SQL/Node imports.
- `packages/materializer`: `TopicKernel` (O(changed) `state/v3`, `$admission.authorize`/`verify` hooks, kernel-enforced monotonic `$seals`, `simulate()`), `QuickJsSandbox` (`quickjs-emscripten-core` + `@jitl/quickjs-ng-wasmfile-release-sync`, scoped `chronolog-pkg/v1` loader, deep-frozen inputs, lazy `readTopic`, deterministic fuel), `WasmSandbox` (`chronolog-wasm/v1`), `evaluateDerivation` + Ed25519 attestations, and audited `STANDARD_MODULE_SOURCES` (`chronolog/{admission,seals,reducer,keys,keybox,vaults,publications,mounts,builders,registry,rls,sql,sqlite-helpers,guards,quotas,queue,votes,schema,audit,crdt,text,ledger,workflow,fs}`).
- `packages/sqlite-cas`: stock SQLite + FTS5 + `sqlite-vec` compiled to static `sqlite-cas.wasm` over a 4 KiB Merkle-paged `CAS` VFS with 3-mode authorizer and deterministic UTC profile.
- `packages/signals`: ephemeral signed live-lane messages with optional `stateRoot`/`supersedesStream` anchoring.
- `packages/peer-session`: unified `ApplicationSession`, `createLogGenesis`, `createRegistryGenesis`, `ApplicationDevice`, `ApplicationSessionOwner` / `WorkerApplicationSession`, `/kernel` (`replayBlindHostControl`, `collectControlReferencedCasHashes`, `dryRunReducerUpgrade`), `/mirror` (WinterCG `createCasMirrorHandler` with `isServableTree`, `createCasMirrorClient`), `/workerd-plugin`, `control-plane.ts` (`materializeControl`), `KeyStore` (`key-store.ts`), the owner wire-method table (`owner-methods.ts`), `connectHttpSync` / `BlindSyncStore` HTTP sync, `createApplicationBackend` (`application-backend.ts`), blueprints, reactive views, encrypted checkpoints, event forwarder, and scoped tools. Passive browser/worker/index entrypoints never eagerly load durable storage, QuickJS, or SQLite-CAS (verified by `tools/package-peer-session.mjs`).
- `packages/pack`: deterministic esbuild reducer packer, determinism linter, npm/JSR tarball ingester, lockfile, and registry client.

## Verification Rules

- Always run `pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm docs:check` before committing.
- Never commit dirty provenance archives into downstream repos (`tendriller` requires `dirty: false` in `provenance.json`).
- Keep `pnpm docs:check` green when modifying any Markdown file.
